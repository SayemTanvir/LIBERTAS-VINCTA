## Story/context findings

- Battery instructions omit units, and the new empty-gadget feedback incorrectly
  says 50 percent. The code threshold is 50 seconds out of 90 (about 56 percent).
  Resolved in player feedback, field guide, README and walkthrough; resource mechanics are unchanged.
- The README describes the cinematic both as a launch sequence and as a New Game
  sequence. Runtime startup plays the cinematic; New Game begins the awakening.
  Resolved the duplicated contradictory instruction without changing the story.
- The short finale checklists omit the Ward Bell even though the detailed guide
  explains it. Added the bell before the held-E step in each checklist.
- The piano is a three-step seal/lock puzzle that gates Hearing. Preserve that
  gameplay while seated visuals are blocked; do not describe an implemented
  endless seated music mode.
- No core plot rewrite is proposed. The family/prison interpretation remains
  deliberately ambiguous as documented in the walkthrough.

The live campaign uses normal engine speed, actual movement and E/Q inputs,
collision-aware approach paths, and active enemy AI. It completes the awakening,
Untouched escape, Roots name reveal, three gadget uses in Echoes, Ward Bell and
Custodian's Rest's real 20-second ritual. The Part II transition calls the same
GameManager method as the outcome screen's Descend button. It does not teleport,
assign progression flags or disable enemies. This is an automated headless
playthrough, not a claim of exhaustive human playtesting.

Canonical/alternate route tests isolate progression and may teleport or disable
AI. The separate finale suite uses live AI and real held-E rituals for all three
endings. This combination covers the other branches without claiming every
branch has received a complete normal-speed playthrough.

A rendered OpenGL checkpoint run passed 32 checks before the later hearing tests

was visually inspected for readable text and menu placement. After removal of
the redundant light gradient, the rendered run emitted no texture-atlas errors.

One concurrent action-animation run failed its beam-timing check; an isolated
rerun passed all 1,646 checks. A concurrent systems run reported shutdown leaks;
the isolated verbose rerun passed and shut down cleanly. Logs also report the
Windows root certificate store error, which is outside these offline gameplay
changes. These observations are retained rather than describing every initial
run as clean. The complete campaign initially reported four objects/two resources
at abrupt test exit; allowing ending callbacks to complete and returning Home
before quitting resolved this. The final verbose campaign rerun passed all 48
checks without resource/object leak warnings.

## Outstanding limits and choices

- **77 furniture placements need real directional views.** Desired inward facing
  is calculated; the existing front art remains until matching assets are supplied.
  No fake rear views, mirrored substitutes or new furniture art were introduced.
- **Piano Stage 1 remains incomplete.** Both generated sheets have RGB-only painted
  checkerboards and the wrong cell grid. Stage 2 remains blocked by asset quality,
  not permission. Existing piano story gates and animation were preserved.
- Freestanding furniture retains authored facing; corners choose the clearer
  inward corridor. Explicit zones describe the existing rectangular floor strips.
- Multiple simultaneous enemies are not an authored game mode and were not
  exhaustively exercised. The target-lifecycle regression tests one enemy with
  absent, deleted and replacement player nodes.
- No changes to room dimensions, route requirements, puzzle answers, enemy speed,
  HP prices, story intent or saved furniture schemas were made by this follow-up.
